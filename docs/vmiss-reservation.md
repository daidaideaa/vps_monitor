# VMISS 年付订单

2026-10-09 按用户授权增加独立锁单功能，目标固定为 JP.TKY.TRI.Basic 一台、年付、Debian 12。**本文说明授权与代码逻辑，当前运行/账单状态必须通过服务状态、私有 SQLite 或 VMISS 官网确认，不能从本文件推断订单已生成。**
优先使用账户余额，剩余金额留给用户通过支付宝支付；程序不访问外部支付网关。

vps-stock-telegram 继续监听目标套餐的四个白名单来源：`@hostmonit`、`@vmisstz`、`@vmiss_com`、`@vmisscom`（客户群仅管理员或群自身非转发消息）。新的有效有货消息通过私有 SQLite
发送信号，vps-vmiss-reservation 核对官网库存和当前账户，准备配置及账单。
初次启动检查官网一次；正常缺货后只在新补货信号到达时访问商家，不增加定时网页轮询。
历史基线、过时消息、其他套餐和仅更新优惠码的消息不触发下单。

结算先验证最新年付适用优惠码，再尝试已验证的 10%OFF；实际金额下降且官网显示
对应优惠码才保留。无效码移除，仍按官网年价准备订单。币种固定 CAD；年付抵扣余额前
总额超过 144 CAD、页面结构变化或配置不匹配时停止并发送人工检查邮件。

提交前写入持久标记。成功识别目标账单后通过原邮件队列通知，停止自动提交。
已存在目标未付款账单或有效服务时同样停止，避免重复购买。提交超时、断电或不明确的
结果只读取账单核对，不重新提交；无法确认时发邮件要求人工检查。
账单生成不保证商家保留库存；库存和未付款订单有效期以 VMISS 规则为准。

私有配置：/etc/vps-observatory-low/vmiss-reservation.json，0600。
cookies、提交状态及生成的服务器密码：/var/lib/vps-observatory-low/vmiss-reservation，0700。
不上传账号、密码、会话、账单或状态到公开 API、网页或 Git。

部署脚本在 vps_build/observability/deploy_vmiss_reservation.py。
只更新库存解析器和新增订单模块，备份旧解析器，仅重启库存监听及启动订单服务。

```sh
systemctl status vps-vmiss-reservation
systemctl disable --now vps-vmiss-reservation
```

成功提交后即使重启机器也不会重新下单。需要再次购买时必须先核对已有服务、订单
和账单，然后由用户明确授权重新启用，不能自动删除提交标记。

**2026-10-09 历史验证**：当时服务器登录成功，目标套餐缺货；这不代表现在缺货。同系列有货套餐仅测试配置和结算预览，
年付及 10%OFF 通过，测试购物车清空，没有提交测试订单。
离线回归覆盖年付、余额优先、支付宝、优惠码回退、错套餐/数量/周期拒绝、重复消息、
重启去重、提交超时、崩溃后核对，以及实际账单 data-url 属性和余额支付状态。
Basic 缺货期间无法完成真实目标订单的最终提交验收。
